# git-url Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Print GitHub file permalinks and warn when the on-disk version is not committed and published.

**Architecture:** A standalone Bash CLI resolves the file's worktree, selects a remote, converts its URL, and emits a HEAD permalink. Git diff and remote-ref reachability provide independent warnings; only `--fetch` permits network access.

**Tech Stack:** Bash, Git, shell integration tests using temporary repositories.

## Global Constraints

- Print a single HTTPS GitHub/GitHub Enterprise commit permalink on stdout.
- Send warnings and errors to stderr; do not open a browser.
- The default is offline: no fetch or other network requests.
- Warnings do not prevent printing the best-effort URL and return exit code 0.
- Invalid arguments return 2; errors that prevent URL construction return 1 and produce no URL.
- Do not modify or commit unrelated existing work.
- Execute in the current checkout, as explicitly selected by the user; do not commit or install automatically.

- [x] Cover clean and dirty files, absent HEAD entries, unpublished HEAD, published descendants, missing remote refs, fetch success/failure, detached HEAD, remote selection, path encoding, symlinks, worktree isolation, malformed inputs, and credential stripping. Assert actual stdout, stderr, exit codes, and repository state.

- [x] Implement argument validation and worktree discovery with quoted paths. Use `git --literal-pathspecs` for file queries. Resolve HEAD once, and construct `/blob/<SHA>/<encoded path>`.
- [x] Convert scp, SSH, HTTP, and HTTPS remotes; reject unsupported schemes, queries, and fragments. Never include URL userinfo in output or raw remote URLs in diagnostics.
- [x] Compare the file with HEAD and index separately, and inspect its HEAD tree entry.
